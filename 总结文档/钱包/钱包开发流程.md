# 浏览器钱包插件各个文件的作用

## inject-rovider.js 的作用

> inject-rovider.js 的作用是为应用提供一个统一的注入点，用于管理和提供钱包相关的依赖和服务。通过这个文件，可以在应用的不同部分方便地获取钱包实例、配置和相关功能，确保钱包的初始化和使用逻辑集中管理，提升代码的可维护性和可扩展性。

> 注入一个 EIP-1193 兼容的 provider，也就是在页面全局挂载window.ethereum，dapp可以直接调用window.ethereum.request()。

- 通过window.postmessage把请求发送给扩展content script，由content script接受并转发到background进行交互，并将结果返回给页面。
- 这是“注入到网页里的 EIP-1193 Provider”。
- 它会在页面全局里挂载 window.ethereum，让 DApp 直接写：
- window.ethereum.request({ method: 'eth_requestAccounts' })
- 关键逻辑就在这里，尤其是 sendRpcRequest：
- 它用 window.postMessage(...) 把 RPC 请求发给当前页面/扩展内容脚本
- 等待来自 content script 的返回消息
- 通过 resolve/reject 把结果或错误返回给 DApp
- 也就是：它是“DApp 看到的钱包对象”，负责把页面里调用的 Ethereum API 转成扩展内部请求

## entrypoints/content.ts

- 这是“浏览器扩展的 content script”，运行在页面上下文中，但它有扩展权限，能调用 browser.runtime.sendMessage
- 它的职责是：
- 注入 public/inject-provider.js 到页面
- 监听页面发来的 postMessage
- 验证消息来源
- 把请求转发到 background script
- 把 background 的结果再发回页面
- 简单说：它是“页面和扩展后台之间的桥”。

## 钱包注入的链路基础

1. content script 运行在页面里
2. 它把 provider 注入到页面全局
3. DApp 用 window.ethereum.request(...)
4. provider 通过 postMessage 把请求发给扩展
5. background 真正处理钱包逻辑
6. 结果再传回页面
