# 浏览器钱包插件各个文件的作用

## inject-rovider.js 的作用

> inject-rovider.js 的作用是为应用提供一个统一的注入点，用于管理和提供钱包相关的依赖和服务。通过这个文件，可以在应用的不同部分方便地获取钱包实例、配置和相关功能，确保钱包的初始化和使用逻辑集中管理，提升代码的可维护性和可扩展性。

> 注入一个 EIP-1193 兼容的 provider，也就是在页面全局挂载window.ethereum，dapp可以直接调用window.ethereum.request()。

- 通过window.postmessage把请求发送给扩展content script，由content script接受并转发到background进行交互，并将结果返回给页面。
- 这是“注入到网页里的 EIP-1193 Provider”。
- 它会在页面全局里挂载 window.ethereum，让 DApp 直接写：
- window.ethereum.request({ method: 'eth_requestAccounts' })
- 关键逻辑就在这里，尤其是 sendRpcRequest：
- 它用 window.postMessage(...) 把 RPC 请求发给当前页面/扩展内容脚本
- 等待来自 content script 的返回消息
- 通过 resolve/reject 把结果或错误返回给 DApp
- 也就是：它是“DApp 看到的钱包对象”，负责把页面里调用的 Ethereum API 转成扩展内部请求

## entrypoints/content.ts

- 这是“浏览器扩展的 content script”，运行在页面上下文中，但它有扩展权限，能调用 browser.runtime.sendMessage
- 它的职责是：
- 注入 public/inject-provider.js 到页面
- 监听页面发来的 postMessage
- 验证消息来源
- 把请求转发到 background script
- 把 background 的结果再发回页面
- 简单说：它是“页面和扩展后台之间的桥”。

## 钱包注入的链路基础

1. content script 运行在页面里
2. 它把 provider 注入到页面全局
3. DApp 用 window.ethereum.request(...)
4. provider 通过 postMessage 把请求发给扩展
5. background 真正处理钱包逻辑
6. 结果再传回页面

## 生成助记词流程

```js
import * as bip39 from 'bip39';
// 原理:生成助记词(BIP39 标准)
// 内部先从系统安全的熵源(CSPRNG,密码学安全随机数生成器)生成 128 位随机熵(默认强度)。
// 将熵计算 SHA-256 校验和,取校验和的前 4 位(128/32 = 4)。
// 把 熵 + 校验和 拼接后,按每 11 位 一组切分,共 (128+4)/11 = 12 组。
// 每组 11 位的数值(0~2047)作为下标,去 2048 个单词的 BIP39 词表中查对应单词。
// 最终得到 12 个英文单词,即助记词,例如 abandon ability able ...。
// 核心思想:把不可读的随机二进制,编码成人可抄写、可校验的人性化单词。
const mnemonic = bip39.generateMnemonic();
// 生成种子
const seedBuffer = await bip39.mnemonicToSeed(mnemonic);
// Buffer → Uint8Array 类型转换
// bip39 库返回的 seedBuffer 在 Node 环境里是 Node.js 的 Buffer 对象。
// Buffer 本质是 Uint8Array 的子类,但为了跨环境兼容(浏览器里没有 Buffer),显式转换成标准的 Uint8Array。
// 这一步不改变数据内容,只是换了个更通用的类型,方便 ethers 库接收
const seed = new Uint8Array(seedBuffer);
// 生成钱包
const hdNode = ethers.HDNodeWallet.fromSeed(seed);
// console.log('Generated HD Node:', hdNode);
// 生成账户
const wallet = hdNode.derivePath("m/44'/60'/0'/0/0");
// ethers.HDNodeWallet.fromSeed(seed).derivePath("m/44'/60'/0'/0/0") 这行代码的原理是：依据 BIP-32 标准，将一个随机种子（seed）作为根起点，通过一系列确定性的哈希与椭圆曲线运算，沿着 BIP-44 规定的层级路径，最终推导出以太坊主网上的第一个默认账户私钥
// 代码中的 derivePath("m/44'/60'/0'/0/0") 遵循了 BIP-44 标准，该路径的每一位含义如下：
// m：代表主节点（Master）。
// 44'：遵循 BIP-44 多币种钱包标准（' 代表硬化派生，即必须使用私钥才能派生下一级，增加了安全性）。
// 60'：以太坊的币种代码（Coin Type）。
// 0'：账户索引（Account），这里指第一个账户。
// 0：外部链（Change），0 通常代表用于接收资金的外部地址。
// 0：地址索引（Address Index），指该账户下的第一个地址。
// 在派生每一层时，ethers 会使用父节点的私钥、链码以及当前层级的索引值（Index）进行 HMAC-SHA512 运算，将结果与父私钥进行特定的模运算（在 secp256k1 曲线上进行加法运算），从而得到子私钥和子链码
const encryptedMnemonic = AES.encrypt(mnemonic, password).toString();
const encryptedPrivateKey = AES.encrypt(wallet.privateKey, password).toString();
```
