# 重构设计技能

## 它是如何工作的

当应用到现有项目时，请按这个顺序进行：

1. **扫描** — 阅读代码库。确认框架、样式方法（Tailwind、原生 CSS、styled-components 等）以及当前的设计模式。
2. **诊断** — 按照下面的审计清单检查。列出所有泛化模式、薄弱点和缺失状态。
3. **修复** — 在现有技术栈上进行有针对性的升级。不要从零重写。改进现有内容。

## 设计审计

### 排版

检查并修复这些问题：

- **浏览器默认字体或到处都是 Inter。** 替换成更有个性的字体。较好的选择：`Geist`、`Outfit`、`Cabinet Grotesk`、`Satoshi`。对于编辑型 / 创意型项目，可将衬线标题与无衬线正文搭配。
- **标题缺少存在感。** 增大展示型文字的尺寸，收紧字间距，降低行高。标题应该显得厚重而刻意。
- **正文过宽。** 将段落宽度限制在大约 65 个字符左右。提高行高以增强可读性。
- **只使用 Regular (400) 和 Bold (700) 字重。** 引入 Medium (500) 和 SemiBold (600) 以建立更细致的层级。
- **数字使用比例字体。** 使用等宽字体，或启用表格数字功能（`font-variant-numeric: tabular-nums`）来处理数据密集型界面。
- **缺少字间距微调。** 大标题使用负向 tracking，小写 caps 或标签使用正向 tracking。
- **所有小标题都使用大写。** 尝试使用小写斜体、句式大小写或小型大写体。
- **孤立单词留在最后一行。** 修复方式：`text-wrap: balance` 或 `text-wrap: pretty`。

### 色彩与表面

- **纯黑背景 `#000000`。** 替换成偏黑、深炭灰或带一点色调的深色（如 `#0a0a0a`、`#121212` 或深蓝色）。
- **强调色过饱和。** 保持饱和度低于 80%。让强调色与中性色融合，而不是嘶吼式发光。
- **不止一种强调色。** 只保留一种。一致性胜过多样性。
- **暖灰与冷灰混用。** 保持同一灰阶家族。让所有灰色都带同一色相（暖或冷，不要混搭）。
- **紫/蓝「AI 渐变」审美。** 这是最常见的 AI 设计指纹。用中性底色和一个精心考虑的强调色替代。
- **泛泛的 `box-shadow`。** 让阴影带有背景色调。使用有色阴影（例如蓝色背景上的深蓝阴影）而不是低不透明度纯黑。
- **平面设计且无纹理。** 为背景增加轻微噪点、颗粒或微图案。纯平面矢量看起来太生硬。
- **完全均匀的渐变。** 通过径向渐变、噪点覆盖或网状渐变打破统一感，而不是标准的 45° 线性渐变。
- **光照方向不一致。** 审核所有阴影，确保它们暗示一个一致的光源方向。
- **浅色页面中出现随机深色区域（反之亦然）。** 一个单独深色背景区块打断了全浅色页面，像是复制粘贴错误。要么坚持整页深色模式，要么保持背景色调一致。如果需要对比，使用同一调色板中稍深的阴影，而不是在奶油色页面中突然跳到 `#111`。
- **空白、平坦的区域没有视觉深度。** 只有文字、没有背景的区域会显得粗糙。添加高质量背景图（虚化、叠加或遮罩）、微妙图案或环境渐变。若没有真实素材，可使用可靠占位源：`https://picsum.photos/seed/{name}/1920/1080`。可尝试在英雄区、功能区或 CTA 区放置轻微的全宽背景图片，即使是低不透明度也能增加存在感。

### 布局

- **所有元素都居中且对称。** 打破对称性，用偏移边距、混合长宽比或左对齐标题来代替居中内容。
- **特征区一排三个等宽卡片。** 这是最泛化的 AI 布局。替换成 2 列之字形、不对称网格、横向滚动或砌体布局。
- **用 `height: 100vh` 处理全屏区块。** 替换为 `min-height: 100dvh`，避免移动端浏览器（iOS Safari）视口异常导致布局跳动。
- **复杂 flexbox 百分比计算。** 用 CSS Grid 替代，确保多列结构更可靠。
- **没有最大宽度容器。** 添加容器限制（约 1200–1440px）和自动边距，避免内容在宽屏上拉伸到边缘。
- **卡片等高被 flexbox 强制。** 允许不同高度，或者当内容长度不同时使用砌体布局。
- **所有边角半径统一。** 让半径变化：内部元素更紧凑，容器更柔和。
- **没有重叠或层次。** 元素平铺在一起。使用负边距创造层叠和视觉深度。
- **垂直内边距完全对称。** 顶部和底部内边距总是相同。光学上应调整——底部内边距通常需要略大。
- **仪表板总是左侧边栏。** 尝试顶部导航、浮动命令菜单或可折叠面板。
- **缺少留白。** 让间距加倍。让设计呼吸。数据仪表板可以密集，但营销页面不应该那么拥挤。
- **按钮没有底部对齐。** 当卡片内容长度不同时，CTA 会随机排在不同高度。将按钮固定在每张卡片底部，使其在不同内容的上方形成整齐水平线。
- **功能列表从不同垂直位置开始。** 在定价表或比较卡中，功能列表应在所有列中从相同的 Y 位置开始。使用一致的列表上方间距或固定高度标题/价格区块。
- **并排元素的垂直节奏不一致。** 当放置卡片、列或面板时，对齐共享元素（标题、描述、价格、按钮）跨所有项目保持一致。基线错位会让布局看起来有问题。
- **数学上对齐但视觉上不对。** 仅通过数学计算居中并不总能看起来“中心”。图标旁文字、圆形播放按钮或按钮中的文字常常需要 1–2px 的光学微调才会感觉正确。

### 交互与状态

- **按钮没有 hover 状态。** 添加背景位移、轻微 scale 或 translate on hover。
- **没有 active / pressed 反馈。** 在按下时添加轻微 `scale(0.98)` 或 `translateY(1px)` 模拟物理点击。
- **过渡瞬时且无持续时间。** 为所有交互元素添加顺滑过渡（200–300ms）。
- **缺少焦点环。** 确保键盘导航有可见焦点指示器。这是可访问性要求，不是可选项。
- **没有加载状态。** 用匹配布局形状的骨架加载器替换通用圆形旋转器。
- **没有空状态。** 一个空白仪表板显示什么都没有，是被忽略的机会。设计一个精心排布的“开始使用”视图。
- **没有错误状态。** 为表单添加清晰的行内错误消息，不要使用 `window.alert()`。
- **死链接。** 指向 `#` 的按钮要么链接到真实目标，要么视觉上禁用它。
- **导航中没有当前页面指示。** 为活动导航链接添加不同样式，让用户知道自己所处位置。
- **滚动跳跃。** 锚点点击会立即跳转。增加 `scroll-behavior: smooth`。
- **动画使用 `top`、`left`、`width`、`height`。** 切换到 `transform` 和 `opacity`，实现 GPU 加速的平滑动画。

### 内容

- **通用名称如 “John Doe” 或 “Jane Smith”。** 使用多样化、真实感更强的名字。
- **伪造的圆形数字，如 `99.99%`、`50%`、`$100.00`。** 使用更自然、杂乱的数据：`47.2%`、`$99.00`、`+1 (312) 847-1928`。
- **占位公司名如 “Acme Corp”、“Nexus”、“SmartFlow”。** 发明符合语境、可信的品牌名。
- **AI 文案模板化俗语。** 永远不要用 “Elevate”、“Seamless”、“Unleash”、“Next-Gen”、“Game-changer”、“Delve” 或 “In the world of...”。写简单、具体的语言。
- **成功消息中的感叹号。** 删除。自信比喧闹更有效。
- **“Oops!” 错误信息。** 改成直接表达："Connection failed. Please try again."（连接失败。请重试。）
- **被动语态。** 使用主动语态："We couldn't save your changes" 而不是 "Mistakes were made."。
- **所有博客发布日期完全相同。** 随机化日期以显得真实。
- **多个用户使用同一个头像。** 每个不同的人都使用独特资源。
- **Lorem Ipsum。** 永远不要使用拉丁占位文本。编写真实的草稿文案。
- **每个标题都大写。** 使用句式大小写。

### 组件模式

- **通用卡片外观（边框 + 阴影 + 白底）。** 去掉边框，或者仅保留背景色，或者仅保留间距。只有在层级需要提升时，才应该有卡片。
- **总是一填充按钮 + 一次级按钮。** 添加文本链接或三级样式，减少视觉噪声。
- **药丸形 “New” 和 “Beta” 徽章。** 尝试方形徽章、旗标或纯文本标签。
- **手风琴 FAQ 区。** 改为并排列表、可搜索帮助或内联渐进式展开。
- **3 卡轮播 testimonial。** 替换为砌体墙、嵌入式社交帖子或单个循环引用。
- **3 层 pricing table。** 用颜色和强调突出推荐套餐，而不仅仅是高度增加。
- **万事皆弹窗。** 对简单操作使用内联编辑、滑出面板或可展开区域，而不是弹出层。
- **仅仅圆形头像。** 尝试椭圆圆角方块或圆角方形，以减少泛化。
- **亮/暗切换总是太阳/月亮切换。** 可使用下拉菜单、系统偏好检测，或将其融入设置中。
- **底部链接农场四列。** 简化，专注于主要导航路径和法定链接。

### 图标学

- **仅使用 Lucide 或 Feather 图标。** 这些是默认的 AI 图标选择。使用 Phosphor、Heroicons 或自定义图标集以增加区分度。
- **“Launch” 一律用火箭， “Security” 一律用盾牌。** 用不那么俗套的隐喻替换（例如螺栓、指纹、火花、保险库）。
- **图标描边宽度不一致。** 审核所有图标并统一成一个笔触粗细。
- **缺少 favicon。** 始终包含品牌化 favicon。
- **过度使用“多样化团队”股票照片。** 使用真实团队照片、自然拍摄或统一插画风格，而不是奇异的库存图像。

### 代码质量

- **div 泥团。** 使用语义化 HTML：`<nav>`、`<main>`、`<article>`、`<aside>`、`<section>`。
- **内联样式和 CSS 类混用。** 把所有样式移动到项目的样式系统中。
- **硬编码像素宽度。** 使用相对单位（`%`、`rem`、`em`、`max-width`）以保证布局灵活。
- **图片缺少 alt 文本。** 为屏幕阅读器描述图片内容。不要在有意义图像上留下 `alt=""` 或 `alt="image"`。
- **任意 z-index 值，如 `9999`。** 在主题/变量中建立清晰的 z-index 规模。
- **注释掉的死代码。** 在交付前删除所有调试工件。
- **导入幻觉。** 确认每个导入都真实存在于 `package.json` 或项目依赖中。
- **缺少 meta 标签。** 添加适当的 `<title>`、`description`、`og:image` 和社交分享 meta 标签。

### 战略性遗漏（AI 常常忽略的点）

- **没有法律链接。** 在页脚添加隐私政策和服务条款链接。
- **没有“返回”导航。** 用户流程中的死胡同。每个页面都要有返回方式。
- **没有自定义 404 页面。** 设计一个有帮助、带品牌风格的“页面未找到”体验。
- **没有表单校验。** 为邮箱、必填字段和格式检查添加客户端校验。
- **没有“跳到内容”链接。** 对键盘用户至关重要。添加隐藏的 skip-link。
- **没有 cookie 同意。** 如果受司法管辖影响，添加合规的同意横幅。

## 升级技巧

升级项目时，可借用这些高影响技巧来替代泛化模式：

### 排版升级

- **可变字体动画。** 在滚动或悬停时插值调整字重或宽度，让文本更有生命力。
- **轮廓到填充的过渡。** 文字从描边状态进入填充状态，在滚动进入或交互时变化。
- **文本遮罩揭示。** 大型排版像窗口，透出其后的视频或动画图像。

### 布局升级

- **破碎网格 / 非对称。** 元素故意打破列结构——重叠、溢出屏幕或通过计算随机偏移。
- **最大化留白。** 大幅使用负空间，迫使观看者聚焦单个元素。
- **视差卡片堆叠。** 页面滚动时，区块像贴纸一样粘住并叠在一起。
- **分屏滚动。** 屏幕两半朝相反方向滑动。

### 动效升级

- **带惯性的平滑滚动。** 脱离浏览器默认滚动，让体验更有电影感、更厚重。
- **错位进入。** 元素按小延迟级联进入，结合 Y 轴位移和透明度淡入。不要一次性挂载全部元素。
- **弹簧物理。** 用弹簧式缓动替换线性缓动，让所有交互元素更自然、更有重量。
- **滚动驱动揭示。** 内容通过扩展遮罩、擦除或与滚动进度绑定的 SVG 路径进入。

### 表面升级

- **真实玻璃拟态。** 不只是 `backdrop-filter: blur`。增加 1px 内边框和微妙内阴影，以模拟折射边缘。
- **聚光灯边框。** 卡片边框会随鼠标动态发光。
- **颗粒和噪点覆盖。** 固定的 `pointer-events-none` 覆盖层带点噪声，打破数字平面感。
- **有色、带色调的阴影。** 阴影带有背景色，而不是泛泛的黑色。

## 修复优先级

按此顺序应用变更，以获得最大视觉影响和最低风险：

1. **字体替换** — 最大的即时提升，风险最低
2. **调色板清理** — 去掉冲突或过饱和颜色
3. **悬停和激活状态** — 让界面看起来更有生气
4. **布局和间距** — 正确的网格、最大宽度和一致内边距
5. **替换泛化组件** — 用现代方案替换俗套模式
6. **增加加载、空状态和错误状态** — 让它看起来更完整
7. **打磨排版规模和间距** — 高端化最后一步

## 规则

- 与现有技术栈协作。不要迁移框架或样式库。
- 不破坏现有功能。每次更改后都要测试。
- 在引入任何新库之前，先检查项目依赖文件。
- 如果项目使用 Tailwind，先确认版本（v3 vs v4），再修改配置。
- 如果项目没有框架，则使用原生 CSS。
- 保持修改可审查且聚焦。小而针对性的改进胜过大规模重写。
